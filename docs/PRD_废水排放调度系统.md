## 1. 产品概述

### 1.1 背景说明

环保车间拥有一个废水储罐（容量 V，可配置），通过 3 条并行处理工序对废水进行处理（各工序处理能力相同，总处理能力 C 可配置）。上游 7 个生产车间间歇性向储罐排放废水，当前排放行为无序，存在以下问题：

- 多个车间同时大量排放，导致储罐液位急剧上升，存在溢出风险；
- 储罐液位剧烈波动，导致处理工序负载不稳定，影响处理效果；
- 缺乏统一调度机制，无法对排放行为提供有效的统筹建议与指导。

### 1.2 目标用户

| 用户角色 | 关注点 |
|---|---|
| 环保车间管理人员 | 储罐不溢出、处理系统稳定运行、异常及时告警 |
| 生产车间管理人员 | 排放等待时间短、排放配额合理、尽量不影响生产 |
| 系统运维人员 | 调度结果可追溯、参数可配置、系统稳定可靠 |

### 1.3 核心价值

1. **防溢出**：通过调度约束保证储罐液位始终在安全范围内；
2. **稳处理**：均衡各车间排放节奏，避免处理工序负载剧烈波动；
3. **少干扰**：在满足安全约束的前提下，尽量减少对生产车间排放的限制；
4. **可追溯**：所有调度结果入库，支持事后查询与分析。

### 1.4 系统定位

本系统定位为**调度建议层（Advisory System）**，而非执行控制层：

- 系统根据当前液位和约束条件，计算并输出各车间的**建议排放速率**；
- 系统**不直接控制**阀门、泵站、PLC 等任何物理执行设备，不强制执行任何排放方案；
- 系统**不采集**各车间的实际执行情况（如实际排放量、阀门开度等），不对执行结果进行任何处理；
- 系统**不构成闭环控制**：每个调度周期独立依据当前液位生成建议后即完成，不跟踪执行状态，不根据执行结果自动调整后续建议；
- 生产车间收到建议后，由车间管理人员自行决定是否按建议执行，系统对执行行为不做干预；
- 告警/紧急区间的"建议停排"含义为：系统输出的建议速率为 0，并生成告警记录通知相关人员；实际停排操作须由人工完成，系统不自动触发任何停排动作。

### 1.5 系统边界声明

为避免对系统能力产生误解，以下明确系统的能力边界：

**系统能做的：**

- 读取人工录入的储罐液位数据；
- 根据配置参数和线性规划模型，计算各车间的建议排放速率；
- 将建议结果、告警记录写入数据库，供相关人员查阅；
- 按调度周期定时生成新一轮建议；
- 在异常液位区间生成高优先级停排建议并通知相关人员。

**系统不做的：**

- 不向阀门、泵站、PLC、DCS 等任何物理设备发送控制指令；
- 不自动执行建议结果（不存在"建议自动生效"的机制）；
- 不采集各车间实际排放量或设备执行状态；
- 不根据车间的执行情况动态修正当前周期的建议；
- 不构成任何形式的闭环控制或反馈控制系统。

> 本边界声明适用于当前版本及所有后续规划版本。系统定位为建议层的约束不随功能扩展而改变（详见第 10.4 节）。

## 2. 核心功能（MVP 范围）

### 2.1 功能清单

| 功能模块 | 功能描述 | 优先级 |
|---|---|---|
| 基础数据管理 | 车间信息、最大/最小排放速率、储罐参数、处理能力的录入与配置 | P0 |
| 数据采集（手动录入） | 当前储罐液位的人工录入（MVP 唯一动态输入） | P0 |
| 调度计算模块 | 基于线性规划，求解各车间本周期建议排放速率 | P0 |
| 排放方案生成 | 输出每个车间在本调度周期内的建议排放速率（m³/h） | P0 |
| 调度结果存储 | 将调度结果、储罐状态写入 Oracle 数据库 | P0 |
| 异常处理机制 | 分级建议机制（分级阈值 + 弹性速率调节），输出分级建议速率，引导车间规避储罐溢出风险 | P0 |
| 调度参数配置 | 储罐容量、处理能力、调度周期、阈值参数等可配置 | P1 |

### 2.2 功能说明

#### 2.2.1 基础数据管理

- 维护 7 个生产车间的基本信息（车间编号、名称）；
- 配置每个车间的最大排放速率（MVP 阶段各车间速率统一预设，后续支持单独配置）；
- 配置每个车间的最小排放速率（管道最低流量要求，MVP 阶段各车间统一预设）；
- 配置每个车间的优先级权重（MVP 阶段统一为 1.0，后续支持差异化配置）；
- 配置储罐容量 V、处理总能力 C、调度周期 T；
- 配置异常处理阈值（预警线、告警线、紧急线）。

#### 2.2.2 数据采集（手动录入，MVP）

- 每个调度周期开始前，由人工录入以下数据：
  - 当前储罐液位（m³）；
- 无需录入各车间待排量：调度模型直接以"各车间当前是否处于排放状态"作为输入（取自车间基础配置中的启用标志 `IS_ACTIVE`），由算法决定建议的排放速率；
- 后续版本升级为液位传感器自动采集。

#### 2.2.3 调度计算模块

- 触发方式：定时自动触发（默认每 30 分钟一次）；
- 读取当前储罐液位、系统配置参数（V、C、T、r_max、阈值）及所有启用车间列表；
- 根据当前液位判断所处区间，应用对应的异常处理策略；
- 调用线性规划求解器（PuLP）求解各车间最优排放速率 r_i（m³/h），作为建议值输出；
- 将计算结果写入调度结果表。

#### 2.2.4 排放方案生成

- 输出内容：每个启用车间本调度周期的建议排放速率（m³/h）；
- 周期内排放量 = 建议速率 × 调度周期时长 T（m³），作为派生字段一并存储；
- 输出形式：写入 Oracle 数据库调度结果表（MVP 阶段不提供查询接口）；
- 输出性质：调度结果为**建议值**，供车间管理人员参考执行，系统不直接控制排放设备。

#### 2.2.5 异常处理机制

采用**分级建议机制（分级阈值 + 弹性速率调节）**：

| 液位区间 | 区间名称 | 系统建议动作 |
|---|---|---|
| < 80% V | 正常区间 | 线性规划正常调度，生成各车间建议排放速率，不额外限制 |
| 80%~90% V | 预警区间 | 在线性规划约束中加入弹性速率上限，按比例压缩各车间建议排放速率 |
| 90%~95% V | 告警区间 | 建议所有车间停止排放（建议速率=0）[高优先级建议]，写入告警记录，通知相关人员 |
| ≥ 95% V | 紧急区间 | 建议所有车间立即停止排放（建议速率=0）[紧急建议]，写入紧急标记，通知人员人工介入 |

弹性压缩公式（预警区间）：

```
速率上限系数 = 1 - (当前液位 - 0.8V) / (0.1V) × (1 - MIN_RATE_RATIO)
```

其中 `MIN_RATE_RATIO` 为最低速率保留比例，默认值 0.3（即最低保留 30% 排放能力），可配置，**允许设为 0**。

**MIN_RATE_RATIO 取值说明：**

| 取值 | 效果 | 适用场景 |
|---|---|---|
| 0.3（默认） | 预警末端保留 30% 速率，平滑过渡 | 管道较长、阀门响应慢，骤降有水锤风险 |
| 0 | 液位趋近 90%V 时速率线性降至 0，完全停排 | 管道支持快速关闭，车间废水可暂存或回流 |

> 设为 0 时，预警区间末端（液位 → 90%V）速率自然归零，与告警区间强制停排无缝衔接，不会产生速率突变。

## 3. 功能流程

### 3.1 主流程（正常调度）

```
[定时触发 / 手动触发]
        ↓
[读取当前输入数据]
  - 储罐当前液位 L（人工录入）
  - 系统配置参数（V、C、T、r_max、阈值）
  - 所有启用车间列表（IS_ACTIVE=1）
        ↓
[判断液位区间]
  - 正常（L < 0.80V）  → 进入线性规划求解（k=1.0）
  - 预警（0.80V ≤ L < 0.90V）→ 计算弹性系数 k，进入线性规划求解
  - 告警（0.90V ≤ L < 0.95V）→ 生成停排建议（建议速率=0），写告警记录，结束
  - 紧急（L ≥ 0.95V）  → 生成紧急停排建议（建议速率=0），写紧急记录，通知人工介入，结束
        ↓
[线性规划求解]
  - 决策变量：各车间排放速率 r_i（m³/h）
  - 求解最优速率分配
        ↓
[生成排放方案]
  - 输出各车间建议排放速率 r_i（m³/h）
  - 推算本周期排放量 v_i = r_i × T（m³）
        ↓
[写入数据库]
  - 写调度结果表（含速率和推算排放量）
  - 更新储罐状态表（记录当前液位及预测下周期液位）
        ↓
[等待下一调度周期]
```

### 3.2 异常处理流程

```
[检测到液位 ≥ 90% V]
        ↓
[生成停排建议：建议所有车间 r_i = 0（高优先级建议，须人工执行）]
        ↓
[写入告警记录（ALERT_LEVEL = 2 或 3），通知相关人员]
        ↓
[液位 ≥ 95% V？]
  是 → 写入紧急标记，通知人工介入处理（系统不自动执行停排）
  否 → 等待下一周期重新评估
```

## 4. 调度算法设计

### 4.1 算法选择

采用**线性规划（Linear Programming）**，使用 Python PuLP 库实现。

选择理由：
- 约束条件明确（容量、处理能力、速率上限），线性规划可精确求解；
- PuLP 轻量、易集成、无需商业授权；
- MVP 阶段约束规模小（7 个变量），求解速度极快（< 1s）。

### 4.2 输入变量定义

| 变量符号 | 含义 | 类型 | 来源 |
|---|---|---|---|
| `L` | 当前储罐液位（m³） | 浮点数 | 人工录入 |
| `V` | 储罐总容量（m³） | 浮点数 | 系统配置 |
| `C` | 处理总能力（m³/h） | 浮点数 | 系统配置 |
| `T` | 调度周期（小时） | 浮点数 | 系统配置（默认 0.5，即 30 分钟） |
| `n` | 当前启用车间数量 | 整数 | 动态读取 WW_WORKSHOP_INFO |
| `r_max` | 每个车间最大排放速率（m³/h） | 浮点数 | 读取自 WW_WORKSHOP_INFO（MVP 阶段各车间值统一） |
| `r_min` | 每个车间最小排放速率（m³/h） | 浮点数 | 读取自 WW_WORKSHOP_INFO（MVP 阶段各车间值统一） |
| `w_i` | 车间 i 的优先级权重 | 浮点数 | 读取自 WW_WORKSHOP_INFO（MVP 阶段各车间统一为 1.0） |
| `k` | 弹性速率上限系数（预警区间启用） | 浮点数 | 实时计算，范围 [MIN_RATE_RATIO, 1.0] |
| `r_i` | 车间 i 的建议排放速率（m³/h）| **决策变量** | 线性规划求解输出（i=1..n） |

> 注：不再有"待排量 d_i"变量。车间只要处于启用状态（IS_ACTIVE=1），算法即为其分配建议速率；实际是否排放由车间自身决定（有废水则按建议速率排，无废水则速率自然为 0）。

### 4.3 约束条件

**约束 1：储罐容量约束（核心约束）**

调度周期结束后，预测液位不超过安全上限：

```
L + Σ(r_i × T) - C × T ≤ V × SAFE_RATIO

等价形式（除以 T）：
Σr_i ≤ (V × SAFE_RATIO - L) / T + C
```

> `SAFE_RATIO` 默认 0.85，可配置。当 L 较高时，右侧值变小，自动压缩总允许速率。

**约束 2：处理能力约束**

所有车间总排放速率不超过处理系统的缓冲上限（允许储罐小量积液）：

```
Σr_i ≤ C × PROCESS_BUFFER_RATIO
```

> `PROCESS_BUFFER_RATIO` 默认 1.2，可配置。

**约束 3：单车间速率上限约束**

每个车间的排放速率不超过其配置的最大值，预警区间时受弹性系数 k 压缩：

```
r_i ≤ r_max × k     （i = 1..n）
```

> 正常区间：k = 1.0；预警区间：k = 1 - (L - 0.8V) / (0.1V) × (1 - MIN_RATE_RATIO)，范围 [MIN_RATE_RATIO, 1.0]

**约束 4：单车间最小速率约束**

```
r_i ≥ r_min   （i = 1..n）
```

> `r_min` 为车间管道最低流量要求，读取自 `WW_WORKSHOP_INFO.MIN_DISCHARGE_RATE`。当约束不可行（如 `n × r_min` 超出容量/处理能力上限）时，求解器返回 Infeasible，按求解失败流程处理（详见 7.4）。告警/紧急区间跳过 LP 求解，直接输出建议速率 0（高优先级停排建议），不受此约束影响。

### 4.4 优化目标

**主目标：最大化加权总排放速率**（在满足约束的前提下，让各车间尽量排放，高权重车间优先获得更多配额）

```
Maximize: Σ(w_i × r_i)
```

> 说明：`w_i` 为车间 i 的优先级权重，读取自 `WW_WORKSHOP_INFO.PRIORITY_WEIGHT`。MVP 阶段各车间 `w_i = 1.0`，目标退化为 `Maximize Σr_i`，约束关于各 r_i 对称，线性规划最优解会均匀分配速率（每个车间获得相同允许速率），天然具备公平性。后续版本可通过调整权重实现差异化调度，高权重车间在约束紧张时将获得更多排放配额。

### 4.5 输出结果

| 输出字段 | 含义 |
|---|---|
| `workshop_id` | 车间编号 |
| `allowed_rate` | 本周期建议排放速率（m³/h），即决策变量 r_i |
| `allowed_volume` | 本周期推算排放量（m³）= allowed_rate × T |
| `schedule_status` | 调度状态（NORMAL / WARNING / ALERT / EMERGENCY） |
| `predicted_level` | 下周期预测液位（m³），写入储罐状态表 |

**下周期预测液位公式：**

```
L_predicted = L + Σ(r_i × T) - C × T
```

> 即：当前液位 + 本周期总排入量 - 本周期处理量。该值写入 `WW_TANK_STATUS.PREDICTED_LEVEL`，用于运维人员评估液位趋势。当所有车间收到停排建议（告警/紧急区间）时，`Σ(r_i × T) = 0`，预测液位 = `L - C × T`（纯消化模式）。

> **输出性质说明**：以上所有输出字段均为**建议性质**，不具备控制指令属性。车间可选择不执行建议，系统不对此做检测或干预。

### 4.6 调度示例

#### 示例一：正常区间（L = 280 m³，56% 容量）

**参数：**
- V = 500 m³，C = 60 m³/h，T = 0.5 h，r_max = 12 m³/h，r_min = 2 m³/h，n = 7
- SAFE_RATIO = 0.85，PROCESS_BUFFER_RATIO = 1.2，k = 1.0

**约束上限计算：**
- 容量约束：Σr_i ≤ (500×0.85 - 280)/0.5 + 60 = 290 + 60 = 350 m³/h（不紧）
- 处理能力约束：Σr_i ≤ 60×1.2 = **72 m³/h**（约束生效）
- 单车间速率上限：r_i ≤ 12×1.0 = 12 m³/h
- 单车间速率下限：r_i ≥ 2 m³/h（不紧，求解值远高于下限）

**求解结果（处理能力约束为瓶颈）：**

| 车间 | 建议速率（m³/h） | 周期排放量（m³） |
|---|---|---|
| 车间1 | 10.29 | 5.14 |
| 车间2 | 10.29 | 5.14 |
| 车间3 | 10.29 | 5.14 |
| 车间4 | 10.29 | 5.14 |
| 车间5 | 10.29 | 5.14 |
| 车间6 | 10.29 | 5.14 |
| 车间7 | 10.29 | 5.14 |
| **合计** | **72.00** | **36.00** |

> 说明：7 个车间对称分配 72/7 ≈ 10.29 m³/h，每个车间在本调度周期（30 分钟）内可排放约 5.14 m³，合计 36 m³ 恰好等于处理系统本周期的满负荷处理量（60 m³/h × 0.5 h = 30 m³）× 缓冲系数 1.2。
>
> **预测液位**：L_predicted = 280 + 36 - 60×0.5 = 280 + 36 - 30 = **286 m³**（57.2%V），液位小幅上升 6 m³。

#### 示例二：预警区间（L = 420 m³，84% 容量）

**参数：** 同上，但 L = 420 m³

**弹性系数计算：**
```
k = 1 - (420 - 0.8×500) / (0.1×500) × (1 - 0.3)
  = 1 - (20/50) × 0.7
  = 1 - 0.28 = 0.72
```

**约束上限计算：**
- 容量约束：Σr_i ≤ (425-420)/0.5 + 60 = 10 + 60 = **70 m³/h**
- 处理能力约束：Σr_i ≤ **72 m³/h**
- 单车间速率上限：r_i ≤ 12×0.72 = **8.64 m³/h**
- 单车间速率下限：r_i ≥ 2 m³/h（不紧，求解值高于下限）

**求解结果（弹性速率上限为瓶颈）：**

| 车间 | 建议速率（m³/h） | 周期排放量（m³） |
|---|---|---|
| 车间1~7（各） | 8.64 | 4.32 |
| **合计** | **60.48** | **30.24** |

> 说明：预警区间弹性压缩生效，各车间速率从 10.29 压缩至 8.64 m³/h（降幅 16%），平稳过渡而非骤停。容量约束收紧至 70 m³/h（更接近实际限制），模型对液位变化敏感。
>
> **预测液位**：L_predicted = 420 + 30.24 - 60×0.5 = 420 + 30.24 - 30 = **420.24 m³**（84.0%V），液位基本持平，处于可控范围。

## 7. 调度策略

### 7.1 调度周期

- 默认每 **30 分钟**自动触发一次；
- 调度周期可通过系统参数 `SCHEDULE_INTERVAL_MIN` 配置；
- 使用 Python APScheduler 或系统任务计划程序（Windows）实现定时触发。

### 7.2 触发方式

| 触发方式 | 说明 |
|---|---|
| 定时自动触发 | 按配置周期自动执行，MVP 阶段主要方式 |
| 手动触发 | 通过调用调度主函数手动执行，用于测试和应急调度（后续版本通过接口触发） |

### 7.3 异常处理策略详细规则

| 区间 | 液位条件 | 建议动作 | 记录动作 |
|---|---|---|---|
| 正常 | L < 0.80V | 线性规划正常求解，输出各车间建议排放速率 | 写调度结果 |
| 预警 | 0.80V ≤ L < 0.90V | 线性规划 + 弹性速率上限 k ∈ [MIN_RATE_RATIO, 1.0]，输出压缩后的建议排放速率 | 写调度结果（状态=WARNING） |
| 告警 | 0.90V ≤ L < 0.95V | 建议所有车间停止排放（建议速率=0）[高优先级建议] | 写调度结果（状态=ALERT）+ 写告警记录 |
| 紧急 | L ≥ 0.95V | 建议所有车间立即停止排放（建议速率=0）[紧急建议，须人工介入] | 写调度结果（状态=EMERGENCY）+ 写告警记录（级别=3） |

### 7.4 求解失败处理

当线性规划求解器返回 Infeasible（无可行解）时：

- 记录求解失败日志（`SOLVER_STATUS = 'Infeasible'`）；
- 生成保守建议：建议所有车间排放速率为 0（系统无法求解最优分配，以保守建议代替，防止溢出风险）；
- 写入告警记录，提示人工排查参数配置；
- 系统不自动执行停排，建议送出后等待人工决策。

## 8. 非功能需求

### 8.1 稳定性

- 调度服务异常退出后，需在 1 分钟内自动重启（通过进程守护或 systemd 实现）；
- 数据库写入失败时，记录错误日志，不影响下一周期调度的执行；
- 线性规划求解超时阈值设为 10 秒，超时则返回保守结果（全置 0）。

### 8.2 实时性

- 每次调度从触发到结果入库，端到端耗时 < 30 秒（含手动录入时间除外）；
- 线性规划求解耗时目标 < 1 秒（7 变量规模，PuLP 可满足）。

### 8.3 可扩展性

- 车间数量扩展：线性规划模型支持动态读取车间列表，新增车间只需在 `WW_WORKSHOP_INFO` 中插入记录即可，无需修改算法代码；
- 处理工序扩展：处理能力通过配置参数管理，新增工序后更新 `PROCESS_CAPACITY` 参数即可；
- 数据采集升级：`WW_TANK_STATUS` 表预留了 `INPUT_TYPE` 字段，后续对接液位传感器自动采集时只需新增数据写入模块，不影响调度计算逻辑。

### 8.4 可追溯性

- 所有调度结果完整入库，包含调度时间、输入参数、求解状态、各车间结果；
- 数据保留策略：调度结果至少保留 6 个月（可按需配置归档策略）；
- **日志保留策略**：日志文件按日期滚动（每天独立文件），保留期限可配置（默认 180 天），超期日志自动清理。

### 8.5 系统边界与无闭环声明

本系统严格限定为**建议层（Advisory System）**，以下边界约束在任何版本中均须保持：

1. **无执行控制**：系统不向阀门、泵站、PLC、DCS 等任何物理设备发送控制指令，不具备执行能力；
2. **无执行采集**：系统不采集各车间的实际执行情况（实际排放量、设备状态、阀门开度等），不存在执行反馈数据入库；
3. **无闭环控制**：系统在每个调度周期独立运行，依据当前输入（储罐液位）生成建议后即完成当次调度；不根据上一周期的执行结果动态修正当前建议，不构成任何形式的自动控制闭环；
4. **建议可拒绝**：车间管理人员有权选择不执行系统建议，系统不对拒绝执行行为进行检测、记录或惩罚；
5. **人工决策保留**：在告警/紧急区间，系统仅输出高优先级停排建议并通知人员，实际停排操作须由人工完成，系统不代替人工决策。

### 10.1 短期优化（v1.x）

1. **传感器集成**：接入 PLC/SCADA 系统，实现液位自动采集，消除人工录入误差；
2. **排放平稳性约束**：在线性规划中引入相邻周期速率变化幅度约束（如 |r_i(t) - r_i(t-1)| ≤ Δr_max），避免车间排放速率剧烈波动；
3. **车间差异化配置**：支持为每个车间单独配置最大排放速率，并通过调整优先级权重（`PRIORITY_WEIGHT`）实现差异化调度（权重字段已预置，MVP 阶段统一为 1.0）。

### 10.2 中期优化（v2.x）

1. **液位预测**：基于历史排放数据，使用时间序列模型（如 ARIMA）预测未来 30 分钟液位趋势，实现前瞻性调度；
2. **多目标优化**：在最大化排放量的同时，引入排放均衡性目标，使用加权多目标线性规划；
3. **可视化监控**：构建实时液位曲线、调度结果展示、告警管理的 Web 界面。

### 10.3 长期优化（v3.x）

1. **强化学习调度**：将调度问题建模为马尔可夫决策过程（MDP），通过强化学习在历史数据上训练最优调度策略；
2. **联动生产计划**：与 MES/ERP 系统集成，提前获取各车间生产计划，实现预测性调度；
3. **数字孪生**：构建废水处理系统的数字孪生模型，支持调度策略仿真验证。

### 10.4 系统定位约束（适用于所有规划版本）

无论未来版本引入何种新功能（AI 智能调度、预测模型、MES 集成、传感器自动采集等），以下原则须始终保持：

- **仍只输出建议**：新功能产生的决策结果仍为建议性质，不转变为控制指令；
- **不参与执行控制**：任何版本均不得向物理设备（阀门、泵、PLC、DCS 等）发送控制指令；
- **不形成闭环系统**：即使引入执行结果采集（如用于统计分析），该数据也不得用于自动修正当前周期的调度建议，不构成反馈控制回路；
- **人工决策始终在环**：系统输出建议 → 人工确认执行的工作模式须持续保持，自动化升级只允许发生在建议生成环节（如预测更准确、算法更优），不允许延伸至执行控制环节。

> 以上约束为系统架构边界约束，如需变更（如升级为执行控制系统），须重新进行安全评估、系统架构评审和需求确认，不得通过功能迭代方式悄然突破。
