## 1. 数据模型设计

### 1.1 前后端数据模型映射

以下表格定义后端 Python dataclass 字段 → 前端 JSON 字段的映射关系。命名规则：
- 后端使用 `snake_case`（Python 惯例）
- 前端 JSON 使用 `snake_case`（与后端保持一致，降低映射成本）

**后端**：`backend/model/schedule_result.py` → `ScheduleResultRecord`

| 后端字段 | 类型 | JSON 字段 | 说明 |

| `schedule_id` | `str` | `schedule_id` | 调度批次号（UUID） |
| `schedule_time` | `datetime` | `schedule_time` | ISO 8601 字符串 `"2026-04-20T10:30:00"` |
| `workshop_id` | `str` | `workshop_id` | 车间编号 |
| `allowed_rate` | `float` | `allowed_rate` | 建议排放速率（m³/h），保留2位小数 |
| `allowed_volume` | `float` | `allowed_volume` | 推算排放量（m³），保留2位小数 |
| `tank_level_before` | `float` | `tank_level_before` | 调度前液位（m³），保留2位小数 |

## 2. API 接口设计

### 2.1 技术选型

| 选项 | 推荐方案 | 理由 |
|------|----------|------|
| Web 框架 | **FastAPI**（已确认 Q1，用户改选） | 内置 Swagger 文档、Pydantic 数据校验、高性能异步框架、`def` 端点自动线程池执行同步 DAO |
| 数据序列化 | Pydantic BaseModel + `dataclasses.asdict()` | FastAPI 内置 Pydantic 校验，复用现有 dataclass 转换 |
| 静态文件服务 | FastAPI `StaticFiles` 中间件 + `HTMLResponse` | 直接复用现有 `frontend/` 目录结构 |
| 跨域 | 不需要 | 前后端同源部署（FastAPI 同时服务静态文件和 API） |

### 2.2 统一响应格式

```json
{
  "status": 200,
  "message": "success",
  "data": { /* 业务数据 */ }
}
```

错误响应：
```json
{
  "status": 400,
  "message": "液位值非法：-1",
  "data": null
}
```

### 2.3 HTTP 状态码与业务错误码映射

| HTTP 状态码 | 业务含义 | 场景 |
|-------------|----------|------|
| 200 | 成功 | 正常查询/操作 |
| 201 | 创建成功 | 新增车间 |
| 400 | 请求参数错误 | 液位非法、必填字段缺失 |
| 404 | 资源不存在 | 调度批次号不存在、车间不存在 |
| 500 | 服务器内部错误 | DB 连接失败、LP 求解异常 |

**业务错误码**（放在 `message` 字段中）：

| 错误码关键词 | HTTP 状态码 | 说明 |
|-------------|-------------|------|
| `INVALID_TANK_LEVEL` | 400 | 液位值非法（≤0 或 None） |
| `NO_ACTIVE_WORKSHOP` | 400 | 无启用车间 |
| `CONFIG_LOAD_ERROR` | 500 | 配置加载失败 |
| `DB_QUERY_ERROR` | 500 | 数据库查询失败 |
| `DB_WRITE_ERROR` | 500 | 数据库写入失败 |

### 3.1 调度概览数据获取

#### 3.1.1 GET `/api/dashboard/overview`

获取 Dashboard 页面所需的全部聚合数据。

**请求参数**：无

**响应数据**：

```json
{
  "status": 200,
  "message": "success",
  "data": {
    "tank_status": {
      "level": 320.50,
      "ratio": 64.1,
      "status": "NORMAL",
      "k": 1.0,
      "predicted_level": 290.30,
      "record_time": "2026-04-20T10:30:00"
    },
    "schedule_results": {
      "total_rate": 52.36,
      "schedule_id": "uuid-string",
      "schedule_time": "2026-04-20T10:30:00",
      "results": [
        {
          "workshop_id": "WS001",
          "workshop_name": "车间1",
          "max_rate": 12.00,
          "allowed_rate": 8.57,
          "allowed_volume": 4.29
        }
      ]
    },
    "alerts": [
      {
        "alert_time": "2026-04-20T10:30:00",
        "alert_level": "ALERT",
        "tank_level": 460.00,
        "level_ratio": 92.0,
        "alert_message": "液位达到告警区间，建议立即停止排放（当前液位460.00m³，占比92.0%）"
      }
    ],
    "active_workshop_count": 7,
    "current_cycle": "2026-04-20T10:30:00",
    "next_cycle": "2026-04-20T11:00:00"
  }
}
```

**后端实现要点**：
1. `tank_status`：从 `TankStatusDAO.get_latest_manual_level()` 获取最新液位，结合 `ConfigService.get_all_params()` 计算 zone/k/ratio
2. `schedule_results`：从 `WW_SCHEDULE_RESULT` 查询最新一次调度批次（按 `SCHEDULE_TIME DESC` 取第一条的 `SCHEDULE_ID`，再按批次聚合）
3. `alerts`：从 `WW_ALERT_LOG` 查询最近 10 条告警（`ORDER BY ALERT_TIME DESC`），`alert_level` 做 int→string 映射
4. `current_cycle` / `next_cycle`：根据 `SCHEDULE_INTERVAL_MIN` 计算当前/下一调度周期对齐时间
5. `active_workshop_count`：从 `WorkshopDAO.get_active_workshops()` 获取长度

**需要新增的 DAO 方法**：
- `ScheduleResultDAO.get_latest_schedule()` → 返回最新一条 `ScheduleResultRecord`（含 `schedule_id`）
- `ScheduleResultDAO.get_by_schedule_id(schedule_id)` → 返回该批次所有车间记录 `List[ScheduleResultRecord]`
- `AlertLogDAO.get_recent_alerts(limit=10)` → 返回最近 N 条告警记录

**需要新增的 DAO 方法**：
- `ScheduleInputDAO.query_records(start_time, end_time, zone, page, page_size)` → 返回 `(total, List[dict])`

### 4.3 实时数据更新机制

**方案选择**：HTTP 轮询（非 WebSocket）

| 对比项 | 轮询 | WebSocket |
|--------|------|-----------|
| 实现复杂度 | 低 | 高（需额外库） |
| 实时性 | ~10秒延迟 | 毫秒级 |
| 适用场景 | 工业数据看板，调度周期30分钟 | 高频实时交易 |
| 当前需求匹配 | ✅ 足够 | ❌ 过度设计 |

**轮询策略**（已确认 Q4：轮询间隔以调度周期为准）：

```
Dashboard 页面激活时：
  ├── 轮询间隔：等于调度周期（默认30秒，从 /api/config 获取 schedule_interval_min 转换为秒）
  ├── 轮询端点：GET /api/dashboard/tank-status
  │             GET /api/dashboard/latest-schedule
  │             GET /api/dashboard/recent-alerts
  ├── 页面不可见时暂停（document.hidden 检测）
  └── 页面切换（iframe src 变更）时停止
```

> **注意**：轮询间隔与调度周期一致，意味着每次轮询恰好能获取最新一次调度的结果。若调度周期较长（如60分钟），可考虑在轮询基础上增加手动刷新按钮。

**数据更新方式**：
- 仪表盘（Gauge）：`chart.setOption({series: [{data: [{value: newLevel}]}]})`
- 柱状图（Bar）：`chart.setOption({series: [{data: newRates}]})`
- 表格：`table.reload('schedule-table', {data: newResults})`
- 告警面板：重新渲染 HTML 内容

### 4.4 错误处理和重试机制

#### 4.4.1 网络错误处理

```javascript
function apiRequest(url, options) {
    return $.ajax($.extend({
        url: url,
        dataType: 'json',
        timeout: 10000  // 10秒超时
    }, options))
    .fail(function(xhr, status, error) {
        if (status === 'timeout') {
            layer.msg('请求超时，请检查网络连接');
        } else if (xhr.status === 0) {
            layer.msg('网络连接已断开');
        } else if (xhr.status >= 500) {
            layer.msg('服务器内部错误，请稍后重试');
        }
    });
}
```

#### 4.4.2 重试策略

| 场景 | 重试次数 | 重试间隔 | 说明 |
|------|----------|----------|------|
| 轮询请求失败 | 3次 | 指数退避（2s→4s→8s） | 失败后暂停轮询，下次调度周期到来时恢复 |
| 表单提交失败 | 0次 | — | 不自动重试，由用户决定 |
| 页面初始加载失败 | 1次 | 3秒 | 重试一次后显示错误提示 |

#### 4.4.3 业务错误处理

| 错误类型 | 处理方式 |
|----------|----------|
| 参数校验失败（400） | 弹出具体错误消息，高亮对应字段 |
| 资源不存在（404） | 弹出"数据不存在"提示，返回列表页 |
| 服务器错误（500） | 弹出"系统异常"提示，不暴露内部错误 |

### 5.4 FastAPI 应用工厂设计

```python
# backend/api/app.py
from fastapi import FastAPI
from fastapi.staticfiles import StaticFiles
from fastapi.responses import FileResponse
from pathlib import Path

FRONTEND_DIR = str(Path(__file__).parent.parent.parent / "frontend")


def create_app(scheduler_svc, config_svc, trigger, pool) -> FastAPI:
    app = FastAPI(
        title="废水排放调度系统 API",
        description="建议层（Advisory System）前后端联调 API",
        version="1.0.0",
    )

    # 将依赖注入对象存储到 app.state，供路由通过 Request.app.state 访问
    app.state.scheduler_svc = scheduler_svc
    app.state.config_svc = config_svc
    app.state.trigger = trigger
    app.state.pool = pool

    # 注册路由
    from backend.api.routes import dashboard, history, schedule, workshop, config, alert
    app.include_router(dashboard.router, prefix="/api/dashboard", tags=["Dashboard"])
    app.include_router(history.router, prefix="/api/history", tags=["History"])
    app.include_router(schedule.router, prefix="/api/schedule", tags=["Schedule"])
    app.include_router(workshop.router, prefix="/api/workshops", tags=["Workshops"])
    app.include_router(config.router, prefix="/api/config", tags=["Config"])
    app.include_router(alert.router, prefix="/api/alerts", tags=["Alerts"])

    # 静态文件服务（JS/CSS/图片等）
    app.mount("/static", StaticFiles(directory=Path(FRONTEND_DIR) / "static"), name="static")

    # 首页路由
    @app.get("/", include_in_schema=False)
    async def index():
        return FileResponse(Path(FRONTEND_DIR) / "index.html")

    # 子页面路由（views/*.html）
    @app.get("/views/{page_name}", include_in_schema=False)
    async def view_page(page_name: str):
        return FileResponse(Path(FRONTEND_DIR) / "views" / page_name)

    return app
```

> **同步 DAO 处理说明**：FastAPI 中，将端点定义为普通 `def`（而非 `async def`）时，FastAPI 会自动在线程池中执行，不会阻塞事件循环。因此现有同步 DAO/Service 代码无需任何改造即可直接使用。仅对纯 I/O 等待场景（如无需 DB 的简单查询）才使用 `async def`。
